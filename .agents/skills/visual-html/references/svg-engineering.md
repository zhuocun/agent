## Generator layout

Write the generator in the language the project already uses for tooling.
Otherwise use Python 3 with the standard library only. Node.js with no
dependencies is the alternative. Keep it in one file until it passes about
1500 lines, then split the primitives into a module beside it.

```text
build_page.py
  SOURCES, FACTS, TERMS     data: sources, facts with status, glossary terms
  THEME, LAYOUTS            color tokens; wide, narrow and single type and spacing
  text_width, wrap, box     measurement
  node, container, edge     primitives shared by every figure
  badge, legend_item
  fig_<name>(layout)        one builder per figure, called once per layout
  legend(), page()          page assembly
  main()                    parse --out, write the file
```

- Let each figure builder take a layout object (`LAYOUTS["wide"]`,
  `LAYOUTS["narrow"]` or, for a single-layout figure, `LAYOUTS["single"]`,
  which uses the wide type sizes) and return one SVG string. The layouts share
  the data and the primitives and differ only in positions and layout tokens.
- Read every size, gap and padding from the layout object. Never write a font
  size as a literal inside a builder.
- Write each SVG text size as a unitless `font-size` attribute on its `<text>`
  element, taken from the layout object. The structural checker reads these
  attributes, and inline `style` and `<style>` font sizes, against the layout
  floors.
- Take the output path from a `--out` argument, with a default inside the
  project, and print the path written. Take no interactive input.
- Start the output with a comment that names the generator by its path
  relative to the repository root, with no timestamp:
  `<!-- Generated by tools/build_page.py. Edit the generator and regenerate; do not edit this file. -->`

## Determinism and escaping

- Use no clock, random number, UUID, hostname, user name or absolute path in
  the output.
- Iterate only over ordered data: lists and insertion-ordered dicts. Sort any
  set before iterating it. In Python, never derive output from `hash()` of a
  string, because string hashing changes between processes.
- Format every coordinate with one function that rounds to one decimal place
  and drops a trailing `.0`.
- Write the file as UTF-8 without a byte order mark, with `\n` line endings
  and a final newline. In Python, open it with `encoding="utf-8",
  newline="\n"`.
- Escape every text node and attribute value with `html.escape(value,
  quote=True)`, or its equivalent, including `aria-label` text. Never insert
  raw HTML from the data.
- Write source links as plain `<a href="https://...">` elements with
  `rel="noopener"`. Accept only `https:` and `http:` URLs from the data.
- Confirm determinism by running the generator twice to two paths and
  comparing `sha256sum` output.

## Fact data

Keep every claim the page shows as data, so that its status decides its
style and its badge:

```python
SOURCES = {
    "S1": {"title": "Release plan, rev. 4", "href": "https://example.com/plan"},
    "S2": {"title": "Load test report", "href": "https://example.com/load"},
}
FACTS = {
    "p95": {"text": "p95 latency 220 ms", "status": "verified", "source": "S2"},
    "beta": {"text": "Public beta", "status": "planned", "source": "S1"},
    "cost": {"text": "Monthly cost", "status": "placeholder", "source": None},
}
STATUSES = ("verified", "inferred", "planned", "proposed", "estimated", "placeholder")
```

- Make the generator raise an error when a fact has an unknown status, when a
  fact other than a placeholder has no source, or when a fact names a source
  that `SOURCES` lacks.
- Render a placeholder with the placeholder style and badge, and never with an
  invented value.
- Build the source list section from `SOURCES`, in order, and link each fact's
  figure element to its source through `data-source`.

## Text width estimation

Estimate the rendered width of a label before sizing its box. This estimate
assumes a system sans-serif font and adds an 8% safety margin. Pass
`cjk_context=True` on a CJK page, where East Asian ambiguous-width characters
such as `“` and `·` render full width.

```python
import math
import unicodedata

NARROW = set("iljI.,:;'|!")
SEMI = set("ftr()[]-/")
BROAD = set("mwMW@%")

def char_em(ch, cjk_context=False):
    if unicodedata.combining(ch):
        return 0.0                       # combining marks, such as U+3099, add no width
    eaw = unicodedata.east_asian_width(ch)
    if eaw in ("W", "F") or (cjk_context and eaw == "A"):
        return 1.0                       # CJK, kana, Hangul, full-width forms
    if ch == " " or ch in NARROW:
        return 0.28
    if ch in SEMI:
        return 0.36
    if ch in BROAD:
        return 0.86
    if ch.isdigit():
        return 0.56
    if ch.isupper():
        return 0.66
    return 0.55

def text_width(text, size, weight=400, cjk_context=False):
    em = sum(char_em(ch, cjk_context) for ch in text)
    if weight >= 600:
        em *= 1.06
    return em * size * 1.08
```

- Treat the estimate as a sizing input, not as proof. Pass 4 measures the
  rendered text in the browser and catches every label that overflows its
  box.
- For scripts outside Latin and CJK, such as Arabic, Devanagari or Thai,
  measure a sample of real labels in the browser first and add a script
  factor to `char_em`.

## Line wrapping and box sizing

Wrap Latin text between words and CJK text between characters. Never break
inside a Latin word. Keep closing punctuation off the start of a line and
opening brackets off the end of a line.

```python
NO_START = set("、。，．,.:;：；！？!?)）」』】〉》”’")
NO_END = set("（(「『【〈《“‘")

def tokens(text):
    out, word = [], ""
    for ch in text:
        if ch == " " or unicodedata.east_asian_width(ch) in ("W", "F"):
            if word:
                out.append(word)
                word = ""
            out.append(ch)
        else:
            word += ch
    if word:
        out.append(word)
    return out

def wrap(text, size, max_width, weight=400, cjk_context=False):
    lines, line = [], ""
    for tok in tokens(text):
        trial = line + tok
        fits = text_width(trial.rstrip(), size, weight, cjk_context) <= max_width
        if fits or not line.strip() or tok == " ":
            line = trial
        elif tok[0] in NO_START:         # hang closing punctuation on this line
            line = trial
        elif line.rstrip()[-1] in NO_END:   # carry trailing opening brackets to the next line
            kept = line.rstrip()
            cut = len(kept)
            while cut > 0 and kept[cut - 1] in NO_END:
                cut -= 1
            if cut > 0:
                lines.append(kept[:cut])
                line = line[cut:] + tok   # the opening brackets, any space after them, then tok
            else:
                line = trial
        else:
            lines.append(line)
            line = tok
    lines.append(line)
    return [l.strip() for l in lines if l.strip()]

def snap(value, grid=4):
    return grid * math.ceil(value / grid)

def box(lines, size, pad_x, pad_y, line_height, weight=400, cjk_context=False, min_w=0):
    text_w = max((text_width(l, size, weight, cjk_context) for l in lines), default=0.0)
    return (snap(max(min_w, text_w + 2 * pad_x)),
            snap(len(lines) * size * line_height + 2 * pad_y))
```

- Size the box from the wrapped lines, so that hanging punctuation widens the
  box instead of overflowing it. An empty label gives a box of padding only.
- When a label wraps to more than two lines, first widen the box up to the
  layout's maximum node width, then shorten the label or split the concept.
  Never reduce the font size below the layout floor.
- Give nodes in one row or column one shared width or height when their
  sizes differ by less than about 20%, so that the grid reads as aligned.
- Place each line with an explicit baseline instead of `dominant-baseline`,
  which renderers treat differently. For `n` lines centered on `cy` with line
  pitch `lh = size * line_height`, line `i` has its baseline at
  `cy + (i - (n - 1) / 2) * lh + 0.35 * size`. Use `text-anchor="middle"`
  with the box center as `x`.

## SVG primitives

Write each primitive once and call it from every figure and from the legend:

| Primitive | Inputs | Output |
| --- | --- | --- |
| `node` | id, x, y, label lines, role, status, layout | `<g data-node>` with a rect and centered text |
| `container` | id, box, label, layout | `<g data-node>` with a rect and a label inside the top edge |
| `edge` | from, to, points, kind, label, layout | `<g data-edge>` with an orthogonal path, marker and label |
| `badge` | text, status, x, y, layout | `<g data-status>` with a pill and its text |
| `legend_item` | sample primitive call, label | the sample glyph and its label |

- Map each role and status to one style class from the grammar table, and set
  colors through CSS classes that read the theme tokens, so that dark mode and
  print switch them in one place.
- Draw text as real `<text>` elements, never as paths or images, so that it
  stays selectable, searchable and measurable.
- Do not use `<foreignObject>`. HTML inside SVG escapes the width estimate and
  renders unreliably in PNG exporters and embed hosts.
- Build an edge's path from its points with straight segments and rounded
  corners, and place its label at the midpoint of its longest segment on a
  `--paper` background rect.

## Shared defs and IDs

Define markers and any reusable symbol once per page, in a hidden SVG before
the first figure:

```html
<svg class="defs" aria-hidden="true" focusable="false" width="0" height="0"
     style="position:absolute">
  <defs>
    <marker id="vh-arrow" viewBox="0 0 10 10" refX="9" refY="5"
            markerWidth="8" markerHeight="8" markerUnits="userSpaceOnUse"
            orient="auto-start-reverse">
      <path class="vh-arrowhead" d="M0,0 L10,5 L0,10 z"/>
    </marker>
    <marker id="vh-arrow-accent" viewBox="0 0 10 10" refX="9" refY="5"
            markerWidth="8" markerHeight="8" markerUnits="userSpaceOnUse"
            orient="auto-start-reverse">
      <path class="vh-arrowhead-accent" d="M0,0 L10,5 L0,10 z"/>
    </marker>
  </defs>
</svg>
```

- Do not put markers inside a figure SVG. At each viewport one layout is
  `display: none`, and a marker defined inside the hidden layout can fail to
  render in the visible one.
- Do not hide the defs SVG with `display: none`, which can stop some browsers
  from rendering referenced markers. Use zero size and absolute position, as
  the defs markup in this section shows, and confirm the arrowheads in the
  screenshots.
- Keep every `id` unique in the document. Prefix figure IDs with the figure id
  and the layout, such as `request-path-narrow-gateway`, and prefix shared
  defs with `vh-`.

## Figure markup and aria-label text

Use this markup for each section and two-layout figure. A single-layout
figure holds one `<svg data-layout="single" role="img" aria-label="...">`
instead of the two layouts:

```html
<section class="vh-section" id="s2" data-section="2">
  <p class="vh-num">02</p>
  <h2>Request path</h2>
  <p class="vh-lead">Every request passes the gateway before a service sees it.</p>
  <figure class="vh-figure" data-figure="request-path">
    <svg class="wide" data-layout="wide" viewBox="0 0 960 420"
         role="img" aria-label="...">...</svg>
    <svg class="narrow" data-layout="narrow" viewBox="0 0 330 780"
         role="img" aria-label="...">...</svg>
  </figure>
</section>
```

- Write the `aria-label` from the figure's data with one function, and use the
  same string in both layouts.
- Start with the figure's thesis, then name the main elements in flow order,
  then the status qualifiers, such as "planned" or "estimated".
- Keep it to one or two sentences, about 250 Latin characters or 120 CJK
  characters, in the page language, with the page's terms.
- Use no layout words: left, right, top, bottom, above, below, column, row,
  wide, narrow, or color names. Do not start with "Diagram of" or "Image of",
  because screen readers already announce the role.
- Do not add a `<title>` beside the `aria-label`. It adds a tooltip and can
  give the figure a second name.
- Keep the defs SVG `aria-hidden="true"` and holding only `<defs>`, so that
  the structural checker treats it as a definitions-only SVG and not as a figure.

## Semantic data hooks

Add these attributes, so that verification scripts and tests select elements
by meaning instead of by position:

| Attribute | On | Value |
| --- | --- | --- |
| `data-section` | `<section>` | section number |
| `data-figure` | `<figure>` | figure id, stable across edits |
| `data-layout` | figure `<svg>` | `wide`, `narrow` or `single` |
| `data-node` | node and container `<g>` | node id, the same in both layouts |
| `data-edge` | edge `<g>` | `from-id:to-id` |
| `data-status` | node, edge or badge `<g>` | one value from `STATUSES` |
| `data-term` | element whose label is a glossary term | term id |
| `data-source` | element that shows a fact | source id |

- Keep hook names and ids stable once a verification script uses them.
- Use `data-node` in pass 4 to check that each label fits its rect, and use
  `data-status`, `data-term` and `data-source` during visual and fact-table
  audits to check status marks, identical text across elements sharing the same
  `data-term` value (ignoring whitespace from line wraps), and source
  traceability.
